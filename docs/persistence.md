# Profile persistence

The profile remains `user://spillway_r16.cfg`, using the existing ConfigFile sections and keys. Time records remain integer ticks; the store does no numerical conversion. Attempts/recordings are outside this store.

`scripts/persistence/profile_store.gd` exposes `read_profile(path)` (error, config, state) and `write_profile(path, config)` (Error). The host must check the read result before changing any sections. A profile may start empty only when both primary and backup reads report not-found; existence checks cannot turn another read error into absence. An unreadable or zero-byte existing file may not.

A write serializes beside the destination as `.tmp`, loads it back and compares the complete encoding. It copies the current readable profile into `.bak.tmp` and atomically replaces `.bak`, then atomically replaces the destination with `.tmp`. On first save the checked new profile also seeds the backup. A failure returns an error, cleans temporary files, and never falls back to writing directly over the destination. A failed replacement leaves the original primary and its other-map records intact. An old `.tmp` is never a source of records.

A missing or unreadable primary can be restored from a readable `.bak`. Before replacing an unreadable primary, the store copies its original bytes to a unique `.unreadable-<time>-<counter>` file beside it. Recovery uses a temporary copy and replacement; failure leaves the primary untouched. Without a readable backup the store refuses to save, preserving the original for manual recovery. Backup recovery restores the previous good generation, so the newest save may be unavailable. Syntactically valid but semantically invalid records still use the host's existing identity/tick validation.

This is a single-writer store. It protects ordinary write/replace failures and interrupted temporary writes, not concurrent independent game processes or physical disk failure. Godot's file APIs do not provide a directory fsync here, so this is not a claim of power-loss durability. No records are invented from an unreadable file.

## Verification

`tests/profile_store_failures.gd` checks integer preservation, permission/replace failure injection, backup recovery, saved unreadable bytes and refusal without a backup. `tests/profile_store_legacy.gd` exercises the host writer against an unreadable profile; the r21 writer fails preservation, the patched writer refuses the overwrite. `python3 -B tests/profile_store_suite.py --out /tmp/r22-safety/profile-suite` runs all five scripts through the pinned shared-lock engine with a fresh source snapshot and private profiles. Use `--only unreadable` for the OS-denied-read case with exact primary/backup byte checks. It includes a real directory-permission failure as well as deterministic injected errors. Remove the evidence directory after reading it.

`tools/check_package.py PACKAGE --out EXTERNAL_DIRECTORY` accepts an exported folder or ZIP. The Linux check uses the exact pinned release template and pack from an empty external working directory and private profile. The opt-in packed `package_probe.gd` (hooked by the host only for `--r22-package-check=RECEIPT`) loads every menu map, restarts and enters checkpoint practice, changes volume, quits, and verifies the stored value in a second process. It exercises production handlers headlessly, not physical mouse/keyboard input or visual acceptance. Logs and `RESULT.json` are retained. Duplicate runtime/pack and profile caches are removed. [Official release templates disable external `--script` overrides](https://docs.godotengine.org/en/stable/tutorials/editor/command_line_tutorial.html#command-line-reference); this probe is included in the tested pack and runs only headless with disabled recordings and an explicit private profile beside its receipt.

The export must include the opt-in host hook and probe module. For source-side checking, add `--probe` to the profile-suite invocation; this checks the same actions and relaunch against a fresh imported source snapshot. Source-side success is not acceptance of a release package.

For Windows, add `--platform windows --linux-pack PATH`. Checks require the official template hash, Godot notices, asset notices matching their source hashes, matching BUILD.json hashes and a byte-identical Linux pack. **Windows is not executed.** A different pack, even one that might be equivalent, is refused.

The export wrapper uses the same Repository Pack preset for both platforms. Assemble a matched verification pair with the checked Linux PCK, pinned Windows template and required notices. First verify both runtime inventories against the same gated commit, then record the reused Linux artifact and update the Windows BUILD pack hash. Independent exports of the same source have produced different pack bytes; reuse the checked resource bytes for the matched pair.

ZIP members cannot traverse outside extraction or create symlinks. `python3 -B tests/test_check_package.py` runs the static negative controls.

`python3 -B tests/profile_store_crash.py --out /tmp/r22-safety/crash-proof` watches only a private primary file and kills its Godot process if an in-place write begins. The readable primary and temporary files sit in a directory that denies replacement. The patched writer must return an error with every primary byte unchanged. Add `--baseline-ref 231b6d2` to reproduce the original writer's truncation after failed rename. This Linux-only permission test requires a non-root user; it never watches a real profile or kills another process.
