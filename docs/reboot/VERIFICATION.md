# Spillway verification

The active acceptance contract is BRIEF.md beside this file. Source reconstruction and all-moves coverage are retired. The old `test_spec_*`, `test_body`, `test_runner_vision`, `test_player`, `test_yard`, `test_yard_run`, `test_feel`, `test_presentation`, `test_integration`, `test_traversal` and old render fixtures remain historical developer material. They test a different controller/world and are not Spillway gates. `scripts/main.gd`, `player.gd`, `moves/`, `level.gd` and `yard.gd` likewise remain inactive historical fixtures. The default scene uses `spillway_main.gd`.

`tools/check-spillway.sh` runs new behavioral checks through native CharacterBody3D collision. These are isolated fixtures: run/brake/reverse, jump grace and expiry, standing air control, look independence, ordinary landing continuity, slide release/jump, flat-ground crouch pumping, real ceiling clearance, ramp/landing seams in four directions/speeds and optional mantle intent/cancellation. Fixture setup may seed a labelled pose/velocity; it is not route proof.

`scripts/spillway_driver.gd` supplies ordinary input events through the native game. It never writes position or velocity. Route traces record the seed, input changes, progress, resets, maximum per-tick displacement and a result denominator. Native screenshots/video establish the rendered view. A precise scripted line is evidence of executability, not discoverability or fun.

Input timing/aim perturbations and failures remain in the checkpoint. Normal-speed uninterrupted safe, fast and missed-jump recovery playback, representative approach/airborne/recovery frames, and an independent critique are separate required evidence. Machine rendering performance must name hardware and renderer. No agent can certify Mike's enjoyment or comfort from automated counts.

Clean records require all three ordered segments and no practice restart/checkpoint respawn since R. Stage entry follows real grounded tagged decks or authored entry regions. Side-wall contact, airborne proximity and cached contacts from a distant reset pose do not count. Reaching the wheel always finishes; missing stages produce an exploration result, no invented splits and no saved best. Route proof rejects exploration finishes. Shallow-water recovery is a valid slower clean line. Bot runs never persist personal records or settings. The game uses a fresh `user://spillway_v1.cfg`, not the old feel profile.

Executed results and their limits are in [RESULTS.md](RESULTS.md). `tests/test_spillway_access.gd` uses labelled authored-level fixture poses and actual mouse/action events; it is separate from normal-spawn route proof. `tools/stress-spillway.py --output=/absolute/path/outside/git` preserves every attempt and hashes runtime sources before and after the complete matrix.

`tests/test_spillway_boundaries.gd` samples each of the three recovery floors at three points on each edge, all four diagonal corners, and four known misleading exit/landing headings. It reads actual floor shape dimensions and drives outward through input events. Setup seeds labelled feet poses and grants checkpoints through actual admission regions. It asserts retained support and no respawn. Native `--boundary-views` is a labelled representative subset, not the92-check full sweep. Genuine jumps over barriers and deliberate falls outside recovery routes still respawn.

The r10 flow change intentionally retires assertions that the wheel must refuse incomplete runs. Replacements require a plainly unrecorded exploration result, actual skipped-stage names and preserved clean records. `test_spillway_access.gd` separately checks legitimate run-up rail hops, one-hop bypasses into catch surfaces and resets from tagged floors. The stress matrix retains its original36 cases and adds5 rail-hop seeds; report both subsets as well as the41-attempt denominator.

The overnight presentation regressions add late crouches through the real sluice gate: both capsule passage and near-eye clearance must hold, followed by normal eye restoration. `test_spillway_audio.gd` checks actual generated loop PCM durations, finite unclipped samples and wrap differences against the normal interior range, across the runtime seed and two alternate seeds. It does not test auditory quality.

`tools/visual-play.sh FROZEN_PCK FRESH_ABSOLUTE_DIRECTORY` launches a hidden native exploration session with isolated records. `tools/visual-play.py --inbox DIRECTORY --keys w --seconds .5` sends ordinary input batches and returns a native screenshot. The bridge uses actual pause input between decisions and writes no player pose, velocity, camera or progress. This tests discovery from successive views; its pauses and optional restarts make it separate from uninterrupted route proof. The raw input/state journal is retained for diagnosis, while normal command replies omit world coordinates.

The stress runner also accepts `--pack /absolute/path/to/export.pck` to execute the exact exported runtime. It records the pack's SHA256, the harness commit, the unchanged 41-case denominator and whether the run completed without a runtime change. Evidence directories must be empty so old traces cannot satisfy a new attempt. The frozen ae0911d9 development pack smoke run finishes 39/41, preserving the known rail-hop seed4 and late-fast seed1 follower stalls. Outer `checkpoints/spillway/overnight/packed-matrix-smoke/` contains the summary and a verified archive of every trace/log. That smoke pass is not final-candidate acceptance.

Run `tools/check-pack.sh /absolute/path/to/export.pck` before packed play or delivery. It loads every active script and shader from an empty external directory and rejects engine errors. Packed matrix mode and visual discovery also run outside the source checkout: launching from the source directory can otherwise conceal an omitted resource by loading the loose file. The selected-resource preset must explicitly include new runtime resources. The first screened development pack failed this check and remains marked rejected; it was never delivered.
